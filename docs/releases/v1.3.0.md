# EFT Task Assistant v1.3.0

## 中文

本版本集中升级**多来源地图、本机持久存档、共享偏好和手机路线同步**。此文件也是发布候选说明；是否正式可下载，以 GitHub Releases 实际资产为准。

### 地图与任务来源

- 可切换 Tarkov.dev、EFTarkov 和 RE3MR，并显示各来源、署名和使用限制。Tarkov.dev 仍提供物品图标与藏身处资料。
- 已导入任务保留原来源、正文与进度；切换来源不重新导入或覆盖。名称相似不代表同一任务/点位，缺少可信坐标时保留任务说明，不借用其他来源的坐标。
- RE3MR 使用官网明确链接且通过访问规则检查的高清原图，可在桌面本机缩放、拖动、全屏及切换参考图；没有经校准的任务点与路线，不将其他来源叠加其上。
- 阵营不明的撤离点单独标示，不因为类型缺失就归入 PMC 或 SCAV。物品图片加载失败有稳定占位，避免每次刷新反复重试闪烁。

### 有界后台缓存

- 启动后台预热所有允许来源，修正此前整个排除 RE3MR 的实现选择；前台当前地图/楼层优先，不重复重启整个预热队列。
- 后台下载最多并发 2、完整解码并发 1；等待网络时不占用全局解码锁。磁盘缓存上限 512 MiB 并采用 LRU，批次另有下载量/新增资产上限。
- 可取消、继续、重新预热。状态区分发现、已有缓存、当前处理、新下载、规则拦截、失败、取消和预算待继续，**本轮完成不等于全部地图已下载或永久驻留**。
- `--no-preload` 只关闭启动预热；`--preload-budget-mib N`、`--preload-max-assets N` 为整数 1–512，默认分别为 512 MiB 和 512 个新增资产。按需和手动取图仍遵守来源规则。
- robots/401/403 或规则核查失败不绕过，也不能用旧缓存掩盖拒绝。上游临时离线时，同一已允许资源可按实现回退，并明确提示 stale/offline。
- Windows 中文“连接被拒绝”等已知网络异常按类型和错误码区分，不再误当权限拒绝；真正的 401/403、PermissionError 和规则拒绝仍优先阻断。robots 过期或没有有效允许时仍可能停止图片读取，离线缓存不是绕过规则的保证。

### 存档继承与恢复

- 正式默认根改为 Windows Saved Games Known Folder 下的 `EFTTaskAssistant`，不依赖 EXE 名字、版本目录、CWD、端口或启动环境的 LOCALAPPDATA。preview 通道另有稳定根。
- 新根没有活动存档时，先只读列出可发现的旧根及计数；**明确选择来源后**才备份并迁移到独立 dataset。多份非空来源不会自动合并、覆盖或按时间猜选。
- 自定义绝对 `--data-dir` 仍支持；运行中导入不会立即覆盖当前 dataset，选择在下次启动生效。路径发现失败或未来 schema 会明确停止/提示，不静默创建备用空档。
- 同根进程写锁阻止合作的新版本重复写入；迁移保留原库和备份。旧版可能不支持锁/schema 检查，回滚时必须使用其保留的原数据根，不能让旧二进制写新版 dataset。

### 偏好、路线和手机

- 钥匙回答、显隐、折叠、藏身处计划、已有材料等已提交状态按档案保存在本机服务端，换本机浏览器/端口可恢复，不再只依赖当前浏览器。
- 偏好使用 revision/CAS 与幂等操作；冲突保留双方快照并要求明确选择。旧端口/origin 尚未上传的浏览器内容须在原页面导出并明确导入；无法自动恢复从未提交的数据。
- 路线按档案/来源/地图/楼层保存，可选颜色和粗细；重试避免重复写入，手机只读同步。未提交的离线队列仍在原浏览器，旧路线缺少来源/楼层时要求明确归属，不猜测搬运。
- 手机二维码列出可用网卡、推荐项及之前有效的地址；配对依旧一次使用、两分钟有效。平板自动分栏，手机保留任务抽屉、地图标注折叠与沉浸视图。
- RE3MR 原图**不向手机/LAN 返回字节**，包括已热缓存的图片；手机可查看限制及手动打开来源网站。未取得作者单独授权，不随包分发原图、不用于公共再托管或商业用途。

### 验证范围与已知限制

- 发布复核额外修复普通任务操作历史中的派生字段导致偏好 HTTP 400、不同 dataset 复用旧离线路线队列、来源明确拒绝被旧 HTML/配置降级为离线、手机省略 source 时的切源竞态，以及 CI artifact 上传输入错误；均补专项回归，不把此前的旧预览包当作已修复包。
- 构建锁定版本、完整源码提交、Python 3.11.17 与 pip 依赖；CI 使用固定 Miniforge/conda-forge Windows 配方，因为 actions/setup-python 的该版本没有 Windows 包。BUILD-INFO 记录本地完整 Python 发行字符串与输入散列，本地 Anaconda 与 CI conda-forge 的运行时来源差异不冒充字节相同。

- Stage4 基线：Python 656 passed、1 skipped、7 subtests passed；JavaScript 39 passed。正式候选新增构建/打包检查及最终准确结果由独立验收报告记录，不拿旧预览结果冒充候选包验收。
- 隔离旧 Stage3 → Stage4 编译迁移未传 `--data-dir`；新编译副本改名、搬移、换 CWD/LOCALAPPDATA/端口后，30 个任务、7 条路线及偏好一致。双实例锁、未来 schema 拒绝、源库保留已验证。
- 本轮只新增真实下载 1 张 Reserve：PNG 5760×3240、6,719,090 bytes；Factory 使用已有单图证据。后台试验发现 123 项，41 缓存、1 下载、8 拦截、73 预算待继续，`all_complete: false`。合成调度覆盖不等于全图真实媒体验证。
- **未实体手机测试，未真实逐图下载/离线验证所有地图，未覆盖所有 Windows 用户及 MSIX 宿主。** 手机/平板为浏览器模拟；离线为隔离进程代理失败模拟，不是真实断网承诺。
- 社区数据不保证当前每个补丁和模式覆盖；RE3MR 无校准任务标点/路线。软件未代码签名，源码 MIT 不覆盖第三方媒体许可。

### 安装、备份和回滚

下载对应版本 EXE，或把 portable ZIP 完整解压到新目录再运行。无需安装 Python；保留旧 EXE，不覆盖旧包。候选和正式文件的准确 commit、依赖、构建流程见 `BUILD-INFO.json`，用 `SHA256SUMS.txt` 校验文件。不同构建机器/时间不承诺字节完全相同。

升级前正常关闭自己的实例并备份完整根目录。首次迁移核对旧根/计数后明确选择；不要创建空档掩盖找错目录。回滚时退出新版本，使用旧 EXE 及原数据根；新版之后新增的进度不会自动倒灌旧版。不要降 schema 号、删除冲突双方，或让旧版直接写新 dataset。参见 [存档说明](../save-data.md)。

正式上传前应固定源码提交/版本、完成候选 ZIP 解压启动，并确认 GitHub 与蓝奏云的目标账号/文件夹/分享范围；正式交付须同步同一个验证包并核对大小与 SHA-256。本候选准备阶段不宣称已经上传。

## English

Version 1.3.0 focuses on **multiple map sources, stable local saves, shared preferences and read-only companion routes**. These notes also describe the release candidate; availability is determined by actual GitHub Release assets.

### Sources and cache

- Switch between Tarkov.dev, EFTarkov and RE3MR with attribution and restrictions. Existing quests retain their own source, text and progress; switching does not overwrite/reimport them. Unknown locations remain explained contexts instead of guessed cross-provider coordinates.
- RE3MR reference originals must be explicitly linked and pass access-policy checks. Desktop zoom/pan/fullscreen work without calibrated quest overlays. Original bytes are not rehosted over mobile/LAN, even when cached; artwork is not bundled. No separate author authorization is claimed.
- All permitted sources participate in startup preheating, replacing the previous blanket RE3MR exclusion. Foreground map/floor requests have priority. Downloads are bounded to two, full decoding to one; a network wait does not hold the global decode lock.
- Disk capacity is 512 MiB with LRU, separate from per-pass download/new-asset budgets. Cancel/resume/restart and distinct discovered/cache/download/block/failure/deferred states prevent false all-map-complete claims.
- `--no-preload` disables startup preheating only. `--preload-budget-mib` and `--preload-max-assets` accept integers 1–512, defaulting to 512 MiB and 512 new assets. Robots failures and HTTP restrictions are not bypassed, including through stale cache fallback. Offline fallbacks are explicitly labelled when permitted.
- Typed Windows connection-refused/time-out failures are distinguished from policy denials even when their localized message contains denial words. Actual 401/403, PermissionError and policy failures still take precedence. Expired or invalid robots evidence can stop image reads; offline cache is not a bypass guarantee.

### Saves and companion behavior

- Production defaults use the Windows configured Saved Games Known Folder, independent of EXE name/location, CWD, port and LOCALAPPDATA. Preview uses a separate fixed root.
- First startup lists discoverable nonempty legacy roots before creating an empty replacement. An explicit source choice precedes backups and shadow-copy migration. Conflicting roots are preserved, never merged or selected by modification time. Imported datasets activate only after explicit next-start selection.
- Path errors/future schemas fail clearly. New cooperating versions use a same-root writer lock. Historical binaries may not honor the protocol: use their preserved original roots when rolling back.
- Submitted key answers, visibility/collapse state and Hideout plans/counts now persist in the PC's profile database. Revision/CAS and idempotence preserve both sides of preference conflicts for explicit resolution.
- Old browser-only state from another origin/port still needs export from the original page and explicit import. Unsent offline route queues stay there. Missing legacy route source/floor information requires explicit assignment rather than guesses.
- Routes are scoped by profile/provider/map/floor with colors and widths; paired phones read synchronized routes without write access. QR address selection exposes interface information and remembers a valid choice. Existing phone task sheet, immersive view and tablet split layout remain supported.

### Evidence and limitations

- Release review additionally fixed derived task-history fields causing preference HTTP 400, cross-dataset offline-route reuse, stale HTML/config fallback after explicit source denials, the mobile omitted-source switching race and an incorrect CI artifact-upload input. Dedicated regressions accompany these fixes; old preview packages are not claimed to contain them.
- Version, full source commit, Python 3.11.17 and pip dependencies are fixed. CI uses a pinned Miniforge/conda-forge Windows recipe because actions/setup-python has no Windows package for this Python patch. BUILD-INFO records the complete local runtime/distributor string and input hashes; local Anaconda and CI conda-forge runtimes are not claimed byte-identical.

- Stage4 baseline: 656 Python tests passed, 1 skipped, 7 subtests passed; 39 JavaScript tests passed. Final candidate build/package checks and exact committed-source results are recorded separately, not substituted with old preview evidence.
- Isolated compiled Stage3-to-Stage4 migration used no `--data-dir`. Moved/renamed Stage4 copies with changed CWD/LOCALAPPDATA/ports retained 30 tasks, 7 routes and preferences. Duplicate-writer refusal, future-schema rejection and source preservation were checked.
- Only one new real original was downloaded: Reserve, PNG 5760×3240, 6,719,090 bytes; Factory reuses earlier evidence. The bounded pass discovered 123 assets: 41 cached, 1 downloaded, 8 blocked and 73 deferred, with `all_complete: false`. Synthetic all-source tests are not real all-map downloads.
- **No physical-phone acceptance, all-map real-image/offline coverage, or exhaustive Windows-user/MSIX-host coverage.** Phone/tablet checks are browser emulation. Offline checks simulate an unreachable upstream proxy in an isolated process, not a guarantee of physical disconnection support.
- Community data does not certify every game patch/mode. RE3MR has no calibrated quest coordinates/routes. Builds are unsigned; MIT code licensing does not relicense third-party media.

### Install and roll back

Run the versioned EXE, or extract the complete portable ZIP into a new folder; no Python installation is required. Keep old binaries/packages. `BUILD-INFO.json` records exact source commit, dependencies and build inputs; verify artifacts with `SHA256SUMS.txt`. Byte-identical builds across machines/times are not promised.

Close your own instance before backing up the complete save root. Confirm the correct legacy source/counts on migration. Roll back with the preserved old EXE and original root; later progress is not automatically copied backward. Do not lower schema numbers, discard conflict snapshots or let unsupported older binaries write newer datasets. See [save documentation](../save-data.md).

Before publication, fix the source commit/version, test the extracted candidate ZIP and confirm GitHub/Lanzou destinations and sharing scope. Formal delivery must upload the identical verified package to both confirmed destinations and verify size/hash. Candidate preparation is not an upload-success claim.
